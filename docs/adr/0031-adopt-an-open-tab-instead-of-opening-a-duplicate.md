# Adopt an open tab instead of opening a duplicate

[ADR-0023](0023-reuse-a-controlled-tab-before-creating-one.md) reused a Controlled Tab already at the requested URL, but a tab the person had open outside the boundary was only counted, never used. An agent told to work on the page the person was already looking at therefore opened a second copy beside it, and the person's tab stayed outside the group. [ADR-0017](0017-create-an-ephemeral-tab-group-for-each-control-lease.md) required an explicit user action before a tab became controlled; the person's request to use that page is that intent, but the connector could not see it.

`tabs_create(url)` now takes an already-open tab at that URL into the session instead of opening another copy, after the session's own controlled tab and a released agent tab of the same host have been considered. Candidate selection prefers the active tab of the focused window, then the most recently accessed tab; it never takes a tab another live session controls, a tab recorded to another host, a pinned tab, an incognito tab, or a tab in a different window when the session already works in one. The adopted tab joins the session's group and is not recorded as an agent tab, so [ADR-0027](0027-close-released-agent-tabs-after-ten-minutes.md)'s ten-minute close never closes a tab the person opened. Only the adopted tab's id, title and redacted URL reach the agent; no other tab outside the boundary is exposed.

## Consequences

The person's tab strip changes when an agent starts work on a page they already have open: the tab moves into the agent's group and carries the agent's favicon mark until the session ends. Adopting the active tab of the focused window is deliberate; when the person already has the page in front of them, using that tab is the outcome they asked for. Ending the session restores the icon but leaves the tab and its group membership alone. A person who does not want a tab adopted can close it or move it out of the group before the agent asks for it. This revises ADR-0023's count-only rule and narrows ADR-0017's explicit opt-in rule: the matching tab is taken in response to the agent's own requested URL, not by enumerating the person's tabs.
